## 一、这个项目是什么（一句话）

**SwarmAlpha 是一个 LLM 多智能体认知治理研究平台**——让多个 AI agent 像人类委员会一样讨论决策，实时检测它们的认知偏差（回声室、极化、权威盲从等），并用非破坏性干预改善集体决策质量。

## 二、为什么值得做

### 2.1 真实问题

多个 LLM agent 一起讨论，**并不必然产生更好的决策**。MAST 论文（Cemri et al., NeurIPS 2025）对 1642 条 MAS 对话轨迹的标注显示：

- **41% 的失败**来自系统设计缺陷（角色违规、步骤重复、停止条件感知错误）
- **31% 的失败**来自智能体间失调（信息隐瞒、忽视他人输入、言行不一）
- **28% 的失败**来自任务验证缺失（过早终止、未验证结论）

SwarmAlpha 的核心问题是：**能否在运行时检测这些失败，并用最小干预修复它们？**

### 2.2 前沿定位

这个方向正处于学术热点期（2025-2026）：

| 论文 | 时间 | 与本项目关系 |
|---|---|---|
| MAST (NeurIPS 2025) | 2025-03 | 教授提供，基础参照，已对齐 3/14 失败模式 |
| LumiMAS | 2025-08 | 实时监控框架（部分重叠） |
| AcMAS (ICML 2026) | 2026-05 | 干预策略研究（部分重叠） |
| Collective Alignment | 2026-05 | 统计物理路线（理论更深） |

**窗口期**：6-12 个月内必须发表核心成果，否则被前沿覆盖。

### 2.3 项目的独特价值

在众多 MAS 治理工作中，SwarmAlpha 仍有 3 个独特点：

1. **5 维认知状态（U/E/I/C/S）作为运行时输出**——其他工作监视 agent 外部表现，我们解析 agent 内部信念结构
2. **非破坏性干预原则**——改变信息流而非信念权重（v2.0 破坏性干预 Δτ=-0.267，v2.1 非破坏性方向正确但需验证）
3. **零额外 LLM 成本的运行时治理**——测量层从已输出数据计算，不调用额外 LLM

## 三、当前真实状态（诚实呈现）

### 3.1 已完成且稳定

| 维度 | 数据 | 验证方式 |
|---|---|---|
| 单元测试 | **435 passed, 3 skipped** | `npx vitest run` |
| 实验数据 | **169 closed-loop runs** | Crisis 80 + Supplier 89 |
| 可复现性 | mulberry32 PRNG + SHA-256 manifest | 确定性种子 |
| 认知治理测试 | **91 测试**（检测器 45 + 引擎 24 + 干预 22） | 零 LLM 调用 |
| 测量层 | R/T/H/F 四变量 + 7 个理论命题验证 | 数值验证 |

### 3.2 已实现但未验证

| 维度 | 状态 | 风险 |
|---|---|---|
| 非破坏性干预效果 | E9 smoke test N=6, **Δτ=0.000** | 功效不足，需 N≥30 正式实验 |
| 6 个认知检测器实证触发 | 仅 E9 有触发记录 | 正式实验未运行 |
| 跨模型普适性 | F16 降级（代码版本混淆） | 需同代码版本重跑 |

### 3.3 已知风险与局限

- **社会热力学窗口已关闭**：Collective Alignment (2026-05) 和 Silence of Machines (2026-03) 已在此方向发表更深入的理论
- **"虚假共识"发现被抢占**：Cost of Consensus (2026) 已做更系统的实证
- **r=-0.10 不显著**：当前数据不足以支撑"虚假共识"作为发现，仅为探索性观察
- **MAST 检测器零实证触发**：3 个 FC2 检测器从未在 MAST-Data 上验证精度

### 3.4 不夸大的声明

> SwarmAlpha 当前不是一个"通用 MAS 治理框架"，而是一个"MAST FC2 失败模式的运行时检测+干预实验平台，用 5 维认知状态作为诊断信号"。若接受这个定位，项目方向正确；若坚持"通用治理框架"叙事，则存在架构性缺口。

## 四、核心创新（哪些是原创，哪些是复用）

### 4.1 绝对原创（论文贡献，不可妥协）

| 创新点 | 代码位置 | 为什么原创 |
|---|---|---|
| F = (1-R) + T·H 作为 MAS 诊断指标 | `src/lib/thermodynamics/MeasurementLayer.ts` | R/T/H 各有物理基础，组合成 F 用于 MAS 运行时治理是原创 |
| 5 维认知状态（U/E/I/C/S） | `src/lib/agent/cognitiveState.ts` | Utility/Evidence/Inertia/Confidence/Susceptibility 的组合是原创 |
| NativeCognitiveEngine 混合计算 | `src/lib/discussion/nativeCognitiveEngine.ts` | 3 个 LLM 自省 + 2 个系统计算的分工是原创 |
| 零额外 LLM 成本的运行时治理 | `src/lib/thermodynamics/MeasurementLayer.ts` | 测量层从已输出数据计算，不调用 LLM |
| 非破坏性干预设计原则（v2.1） | `src/lib/governance/cognitiveInterventions.ts` | "改变信息流不改变信念权重"原则是原创 |
| content_driven 发言意愿 5 因子分解 | `src/lib/discussion/asyncEngine.ts` | 5 因子分解是原创 |

### 4.2 复用前沿工作（零风险）

| 复用对象 | 用途 | 复用方式 |
|---|---|---|
| MAST-Data (1642 traces) | 验证检测器精度 | HuggingFace 下载，作为实验输入 |
| MAST LLM-as-judge pipeline | κ=0.77 对照基线 | 外部 Python notebook |
| MAST 14 失败模式定义 | 检测器设计需求源 | 概念参考 |
| Kuramoto 序参量 / Shannon 熵 / Helmholtz 自由能 | R/T/H/F 计算 | 公式实现 |

## 七、协作模式（四种可选，可组合）

### 模式 A：阶梯式任务认领（推荐入门）

**机制**：
1. 你从"低门槛任务"中认领一个
2. 完成后与项目作者 review
3. 逐步进入"中门槛任务"
4. 最终可挑战"高门槛任务"

**优点**：低风险，渐进学习，有明确产出
**缺点**：节奏较慢，可能感觉像"做作业"
**适合**：初次接触项目，想先了解再深入

### 模式 B：子项目负责制

**机制**：
1. 你认领一个完整子项目（如"MAST-Data 验证"或"FC1 检测器实现"）
2. 独立负责设计 + 实现 + 测试
3. 项目作者提供指导但不代写

**优点**：自主性强，产出完整，可能的论文署名
**缺点**：需要较强的自学能力，前期可能迷失
**适合**：有较强工程基础，喜欢独立工作

### 模式 C：学习 + 实践阶梯制

**机制**：
1. 第 1-2 周：阅读 MAST 论文 + 项目 SOT.md + ARCHITECTURE.md
2. 第 3-4 周：运行现有实验，理解代码流程
3. 第 5-8 周：开始做低门槛任务
4. 第 9 周后：进入中门槛任务

**优点**：基础扎实，不容易犯错
**缺点**：前 4 周无产出，可能感觉"光读不练"
**适合**：想深入理解项目，时间充裕

### 模式 D：结对编程（与项目作者）

**机制**：
1. 每周固定 1-2 次线上结对编程（Zoom/Tencent Meeting）
2. 共同完成一个任务
3. 实时讨论设计决策

**优点**：学习最快，直接获得指导
**缺点**：时间协调成本高，项目作者时间有限
**适合**：有重叠时间，想快速学习

### 推荐组合

**对初次接触的本科生**：模式 A（阶梯式） + 模式 C（学习+实践）
- 前 2 周阅读 + 运行实验
- 第 3 周开始认领低门槛任务
- 1-2 个月后进入中门槛任务

## 九、如何开始（第一步）

### 第一步：了解项目（1-2 小时）

1. 阅读 [SOT.md](./SOT.md) §1-§3（项目概览 + 核心数字）

```bash

npm install

# 运行测试

npx tsx experiments/campaign/run_all.ts --only e9_smoke
```
